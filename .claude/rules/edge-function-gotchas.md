## Edge function internals (gotchas)
- **Live tool defs are in `supabase/functions/osint-agent/tool-registry.ts`** (`buildTools`), **not** inline in `index.ts` (which now only orchestrates the request). The god-file refactor moved them; `index.ts` has zero tool defs. The catalog↔runtime contract test (`src/test/catalog-guidance.test.ts`) reads `tool-registry.ts` (with an `index.ts` fallback) to assert every `catalog.ts` entry has a runtime def — keep `catalog.ts` and `tool-registry.ts` in sync when adding a tool. (Any older `tools/*.ts` files are stale mirrors, not the runtime source.)
- **Edge tests live in `supabase/tests/<fn>/`, NOT in the function folder (since 2026-10-15).** Lovable's `supabase--deploy_edge_functions` uploads the whole function folder and the platform refuses >4.5 MB; `osint-agent` measured 4,614,744 bytes on 2026-10-15 (1.95 MB of it `*_test.ts`) and the deploy failed. The tests, `_test_env_*.ts` and `lib/fixtures/` moved to `supabase/tests/osint-agent/` (same `lib/`/`tools/` layout) and `supabase/tests/evidence-export/`, importing runtime code via `../../functions/<fn>/…`. `src/test/edge-deploy-bundle.test.ts` fails on any test file under `supabase/functions/` and on `osint-agent` > 4,300,000 bytes. Source-reading tests resolve runtime files against `../../functions/osint-agent/`, never `./`.
- Tests: `npm run test:edge` (= `cd supabase/tests/osint-agent && deno test --config=../../functions/osint-agent/deno.json --no-check --allow-net --allow-env --allow-sys --allow-read . ../evidence-export` — `--config` keeps the function's own `deno.json`/`deno.lock`, and stops the root `deno.json` from taking over). ⚠️ **It passes DIRECTORIES, not a `*_test.ts` glob** — #597 changed this because the glob matched the osint-agent top level only and five test files had never run. Do not "simplify" it back to a glob, and put new edge tests wherever they belong rather than at the top level. **`--allow-read` is required** — the source-level wiring tests (`reviews_wiring_test.ts`) read `index.ts`/`cluster.ts`/`recovery.ts` off disk to assert the call sites exist, and without it they abort with `NotCapable` before any assertion runs, which reads like a code failure and is not. (The old `--allow-net --no-check` form left env/sys perms off, inflating the failure count — measured 2026-07-25: `--allow-net --no-check` = 546 pass/57 fail vs `--allow-net --allow-env` = 754 pass/24 fail.) **Edge baseline: 2821 passed / 0 failed / 6 ignored** on `main` at `6596812` (re-measured 2026-10-30; the 2626/`ad3c3952` and 1885/`ad4937b` figures are stale) (post-#597, which widened the runner to directories; the 1845/`0a04e1b` figure was the same suite under the old glob, so that jump is COVERAGE, not new tests. Re-measured with `--no-lock`; the 1845/`0a04e1b`, 1832/`95b8d50`, 1802/`c5a0467`, 1762/`d11f2f9`, 1634/`4a5eb1c`, 1624/`57c0912`, 1613/`2026-09-02`, 1539, 1517/`3b6fc44`, 1461/`3c2ef26`, 1446/`cf06cbb`, 1407/`03f64e4`, 1279/`5cc1940` and 1178/`394cd0b` figures are all stale, INCLUDING the "1778" this line briefly carried — that was the mid-branch figure before the promotion-quarantine tests landed). The 24 environmental failures are GONE — do not treat any failure as "probably environmental"; that excuse is retired. **Deno is NOT preinstalled** in the web/remote sandbox: `DENO_INSTALL=/usr/local sh <(curl -fsSL https://deno.land/install.sh) -y` (verified working 2026-08-28 — `dl.deno.land` answers 200 now, so the npm-registry workaround in `mem/ops/deno-tests-in-web-sandbox.md` is a fallback, not the only route). Pass `--no-lock`: an unqualified `deno test` rewrites `deno.lock` and drops four real dependency entries — or skip the install entirely and **use CI as the edge instrument**: any PR gives a clean `deno test` on a provisioned toolchain, and a red PR is still a usable measuring device if you read the per-job conclusions rather than the top-level X. `deno check index.ts` has ~12–157 **pre-existing** AI-SDK/Supabase type-graph errors — not a gate; verify your change adds none.
- **Frontend baseline: 2965 passed / 1 skipped / 247 files** (`npx vitest run`, re-measured 2026-10-30 on `main` at `6596812`; the 2773/222 (`ad3c3952`) and 2106/1/173 (`ad4937b`) figures are stale) (previously re-measured 2026-09-13T00:05Z on `main` at `95b8d50`, post-#587/#588. Use `npm ci`, `npm run typecheck|lint|test|build|test:edge`.
- **⚠️ `npm run test:e2e` EXISTS and PR CI does not run it — run it by hand before merging any workspace change.** This line used to say the script did not exist; it does (`playwright test`, 54 specs over `e2e/workspace-tabs.spec.ts` and `e2e/case-integrity.spec.ts`, driving the harness build). The `e2e` job in `ci.yml` is `if: github.event_name == 'push'` — a deliberate cost call after #483 drained the Actions allowance — so it runs on pushes to `main` **only**.
